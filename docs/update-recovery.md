# Claude 更新退出后的配置恢复

恢复依据有两条：

- 官方应用版本变化附近，原先运行的配置退出，且 Claude 已重新启动（旧版兼容路径）。
- 配置在本次进程生命周期结束时写入了新鲜的 `lastQuitCleanup.for_update = true`。这条路径不要求应用目录已经换成新版本，也不要求默认配置重启。

进程的 PID 和启动时间必须在它仍然运行时保存为快照。`NSRunningApplication.launchDate` 在本机测试中呈现惰性读取行为：生前从未读取过时，退出后首次读取会返回 `nil`。不能用已经退出的对象补取启动时间，否则有效的更新退出记录也会被当作未知而忽略。

第二条读取配置自己的 `config.json`，只读退出原因和时间，不读取聊天或登录信息。退出记录必须晚于对应进程启动，且距离观察到退出不足 30 秒，以免把上次启动遗留的标记用于本次退出。该字段属于 Claude 内部实现，未来版本可能改变；无法解析时保留旧版兼容路径。新鲜的普通退出记录会取消恢复，避免用户正常退出时被重开。

恢复请求与恢复成功分开：

1. 明确更新退出后留出 15 秒交接时间；兼容路径继续等待版本和重新启动信号。
2. 用配置自己的数据目录请求启动，显示“正在重新打开”。
3. 只有正确配置的同一进程持续至少 6 秒，才提示“已重新打开”。默认配置和短暂启动都不能充当成功证据。
4. 每次请求后等 15 秒；最多请求三次。失败后停止并提示手动打开，保留日志中的请求次数与结果。
5. 成功提示涉及的配置后来停止时，清除成功提示。用户通过 Personas 退出配置或关闭恢复设置会取消待恢复操作。

恢复成功只代表进程恢复运行，不保证聊天窗口可见、登录完成或原任务自动继续。不会为了让更新完成而退出仍在运行的其他配置。

## 验证

```bash
./build.sh --no-install
build/ClaudePersonas.app/Contents/MacOS/ClaudePersonas --selftest-update
./scripts/test.sh
```

回归覆盖：应用版本和默认进程不变时的更新退出、延迟启动、错误配置进程、短暂出现后退出、PID 更换、稳定运行确认、三次失败上限、取消恢复，以及退出记录的新鲜度与普通退出判断。测试使用模拟时间和临时配置文件，不操作真实 Claude。

真实 Claude 的更新过程仍需后续端到端观察；模拟测试不能证明上游未来版本的行为。

## macOS 原生进程回归

```bash
./scripts/test-update-exit.sh
```

需要 macOS 图形登录会话。脚本编译并启动临时测试应用，由该应用写入更新退出记录后自行退出，再用生产代码保存的进程快照识别退出原因。它不启动或停止真实 Claude，也不修改用户配置。该测试单独运行，普通自测的模拟日期不能代替它。

2026-10-23 后续调查复现了 0.3.1 遗漏的边界：默认实例不重启、版本不变化时，启动时间此前可能从未被访问；退出后才读会得到空值。旧原生复现失败，运行时保存快照后通过。新增日志记录配置进程出现、停止时的 PID 和更新退出识别结果，未知原因也会记录，避免无声跳过。
